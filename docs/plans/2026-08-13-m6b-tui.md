# fpd M6b, The TUI

> Execute task-by-task. Every task ends at a hard stop for review and commit.

**Goal:** `fpd tui`, a live view of connections showing which bytes produced each fingerprint.

**Architecture:** `ratatui` over `crossterm`, inside the `fpd` binary crate. Records arrive from one of two sources behind a single channel: an attached `fpd serve` admin socket, or a listener this process owns. Rendering is pure, taking state and a frame, so it can be tested against `TestBackend` with no terminal.

**Tech Stack:** `ratatui`, `crossterm`, the existing `fingerprint-probe` and `fingerprint-core`.

## What M6a already provides

Spans on `TlsFingerprint::provenance`, the ClientHello bytes on `ClientReport::raw_hello`,
a bounded `ConnectionLog`, and a JSONL admin socket carrying all of it. This milestone
adds no data. It renders what exists.

## Global Constraints

- MSRV 1.88. Deny lints as everywhere else. Plain punctuation in committed prose.
- The terms gate covers the whole binary, so `fpd tui` inherits it.
- **One ink.** The visual specification in the M6a plan is the requirement, not a
  suggestion. No hue is assigned to anything.
- Rendering must be a pure function of state, so it is testable without a terminal.
- No test may require a TTY.

## Commit Protocol

**The implementer never runs `git commit` or `git push`.** Stop at each task, print the command, wait.

### Task 1: Records from either source

**Files:** `crates/fpd/src/tui/mod.rs`, `crates/fpd/src/tui/source.rs`

**Interfaces:** `Row` (a rendered-ready record), `parse_frame(&str) -> Option<Frame>`,
`Frame::{Record(Box<Row>), SnapshotEnd}`, `attach(path) -> mpsc::Receiver<Row>`,
`listen(addr) -> mpsc::Receiver<Row>`.

Attach parses the JSONL the admin socket emits. Standalone binds a probe and captures.
Both produce the same `Row`, so nothing downstream knows which is in use.

- [ ] Tests: a record frame round-trips into a `Row` with its spans and bytes intact, a
      `snapshot_end` frame parses as such, a malformed line is skipped rather than
      killing the stream, and a `seq` jump is detectable as a gap.
- [ ] STOP, commit.

### Task 2: One-ink rendering

**Files:** `crates/fpd/src/tui/theme.rs`, `crates/fpd/src/tui/render.rs`

**Interfaces:** `Ink::{Recede, Normal, Advance, Demand}`, `render(&State, Rect, &mut Buffer)`.

- [ ] `Ink` maps to `Style` using only `DIM`, default, `BOLD` and `REVERSED`. **No
      `Color` is ever constructed.** A test asserts that, by scanning the rendered
      buffer for any cell whose foreground or background is not `Color::Reset`.
- [ ] The hex pane renders inert bytes, the random field and session id, as dim `··`,
      and fingerprint-relevant bytes at normal weight, so provenance shows as contrast.
- [ ] Responsive breakpoints from the visual spec, asserted at each width.
- [ ] STOP, commit.

## Self-Review

**Spec coverage.** §6.7 `fpd tui` attaching over the admin socket maps to Tasks 1 and 3.
The bounded in-memory buffer is inherited from M6a. The chosen visual direction maps to
Task 2.

**Known risks.**

1. **Standalone mode captures and closes.** It reuses `Probe`, which has no upstream to
   forward to, so a client sees the connection close after its request. That is fine for
   inspecting a client and it makes the demo one command, but it is not a proxy and the
   docs must not imply it is.
2. **Terminal restoration on panic.** The deny lints make a panic unlikely, but a panic
   hook that restores the terminal is still required, because the failure mode is the
   user's shell rather than the program.
3. **`TestBackend` proves layout, not looks.** It can assert that no colour is used and
   that content lands in the right cells. It cannot tell whether the result reads well,
   so the screenshot in the README is the honest check.
